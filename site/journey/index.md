# 从 0 到 1：把一桌资料编译成 Ontology

前面各讲是「拆开来看」：先讲什么是 Ontology，再剖析开源实现、LLM Wiki、MPS 与本项目架构。这一课反过来 —— **先不给任何结论，只给你一桌子乱七八糟的东西**。

桌上摆着 7 份材料：两份互相打架的规章、一段夜班交班访谈、三套命名各异的医院数据库、还有一句随口说出的业务需求。你要做的，是把它们一步一步编译成一份**权威本体（Canonical Ontology）**，然后用它回答最开始那个问题。

::: tip 这一课怎么玩
- **七幕流水线**，每幕有一个必须亲手完成的小任务，完成后才解锁下一步；右侧讲解栏始终回答「这一步在做什么 / 为什么不能直接建图 / 交给下一步的产物是什么」。
- 点 **▶ 自动演示** 可以完整看一遍；点 **⛶ 全屏沉浸** 进入无干扰模式（`Esc` 退出）；给链接加上 `?autorun=1` 可以打开即播放，适合课堂投屏。
- 允许犯错：标错模态、合并错概念、选错消解维度，都会当场展示真实后果，随时重试或跳过。
:::

## 走完之后，再看这张对照表

刚才你亲手做过的每一步，在 `GLOSSARY.md` 里都有严格定义。把它们对上号，再去读架构章节会轻松很多：

| 你刚才做的事 | 项目里的正式名字 | 为什么不能跳过 |
| --- | --- | --- |
| 把 7 份材料原样收进编译器 | 原始资料（Source） | 一旦先让 LLM「整理成文档」，原始措辞与矛盾点就被抹平，结论将无法回溯 |
| 扫描并挑出 3 条能引用的句子 | 资料片段（Fragment） | 证据粒度必须精确到条款与时间戳，否则无法验证 |
| 给 4 条主张标注模态 | 事实主张（Claim） | 「发生过」不等于「被允许」；把违规观察当规范会让系统学坏 |
| 把三个字段名挂到同一个 ID | 概念注册表（Concept Registry） | 跨源方言必须由稳定身份统一，且要区分同义关联与概念合并 |
| 按适用范围拆成两个指标 | 证据图（Evidence Graph）与冲突消解 | 消解不是删除矛盾，两条主张与裁决依据都要留档 |
| 把自然语言规则拼成 AST | 策略约束（Policy）与类型检查 | 提示词约束会被长上下文绕过，只有确定性守卫能兜住 |
| 点节点看溯源、切三视图、回答问题 | 权威本体（Canonical Ontology）与模型投影（Projection） | 模型是唯一事实源，看板、代码、Agent 工具都只是它的投影 |

最后那个答案对比值得多看一眼：同一个问题，「把文档直接丢给 LLM」和「经本体守卫的 Agent」给出的结果差别，不在模型能力，而在**有没有一份受约束、可追溯的业务契约**。
