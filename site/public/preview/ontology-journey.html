WHY / 为什么需要稳定 ID

如果每次查询都靠字段名猜，Agent 就得同时记住三套系统的方言。

有了稳定 ID，visit_no / inp_id / encounter_id 只是同一个概念的三个别名 LINK_ALIAS，模型层只有一份定义。

⚠ 陷阱题：患者 ID 与医保付款人 ID 在 95% 的记录里数值相同，要怎么处理？

直觉会说「合并吧」。但概念一旦合并，Payer 的动作就会错误地绑到 Patient 上，而且下游所有生成物都跟着错。

候选本体要过确定性编译器这一关：类型、稳定 ID、状态机、策略 AST 全部静态校验。注意终端里那条 FAIL —— 自然语言写成的「仅主治医师可确认出院」不能当执行规则，请把它组装成类型化 AST。

Policy AST 组装台

把自然语言规则拆成「主体 + 前置条件 + 动作」三段。只有全部选对，编译器才会放行。
WHO / 主体
WHEN / 前置条件
DO / 受控动作
等待类型化策略通过。生产语义永远不由 LLM 拍板：LLM 负责提议，编译器负责裁决。
