## 一、本课要解决的问题

前两课一共交付了四个实验台：编译预览、来源标记分类、六道守卫轨迹、故障注入。每个都能点、都能跑、都会给出绿色的 PASS。

于是有一个不太舒服但必须问的问题：**这些都是浏览器里的确定性规则推演。凭什么说规则本身是对的？**

[《最小验证实验（MVP）与综合自测》](/architecture/mvp-and-quiz) 已经给出了 Experiments A/B/C 的 PASS 判据和 12 道自测题，但那些是**验收标准**，不是本次已经跑出来的结果。本课把「标准」和「证据」分开：给出一份独立于实现的期望值，再用一个故意失败的版本演示——当测试也由同一套实现生成时，它连明显的数值错误都抓不住。

## 三、当前办法哪里不够

一个常见的「省事」做法是：让生成器同时产出规则实现和对应测试。看起来测试覆盖齐全，实际上两者可能共享同一个误解。

`〔COURSE_DESIGN〕` 下面这段是教学用的**故意失败版**，不是本仓库代码：

```ts
// 实现：把检验明细 JOIN 进来后直接计数（错误口径）
const metric = released + 2
// 测试：期望值直接取自实现（自证）
expect(metric).toBe(implementation.metric)  // 永远是绿的
```

可观察的失败不是「报错」，而是**什么都没报**：指标从 3 膨胀到 5，断言依然全绿。真正能抓住它的，只有一份不依赖这套实现、由课程业务基线人工核对出来的期望值。

另外两种同样无效的替代：用截图或 LLM 评价代替数值断言；把断言容差放宽到足以容纳错误。前者不可判定，后者等于取消断言。

## 四、新概念及最小例子

### 独立 Oracle（独立黄金期望值）

`〔COURSE_DESIGN〕` 本课把「期望值」定义为：由 4 位患者的固定 fixture 和已发布规则**人工核对**出来的查表结果，单独存放，不调用被测逻辑。

| 模型版本 | 危急值 | 科主任终审 | 期望放行 | 期望指标 | 期望拦截 |
|---|---|---|---|---|---|
| v1 | 未清零 | 缺签 | 1 | 1 | 3 |
| v1 | 已清零 | 已补签 | 3 | 3 | 1 |
| v2 | 未清零 | 缺签 | 2 | 2 | 2 |
| v2 | 已清零 | 已补签 | 4 | 4 | 0 |

这张表是**业务基线**，不是从实现里导出的。它与 [《一条规则改下去》](/practice/change-set) 的影响集合表同属一类产物：先由人确定「应该是什么」，再让程序去比对。

### 断言分层

`〔COURSE_DESIGN〕` 本分组把验证分成四层，逐层收窄：规则/领域单元测试 → API 与工具契约 → 负向权限用例 → 少量关键浏览器 E2E。不把覆盖率数字当唯一质量目标，因为生成的实现与生成的测试可能一起错。

### 明细 JOIN 膨胀

「完成出院协同医嘱数」应当按医嘱去重后计数；把检验明细 JOIN 进来再 `SUM`，同一条医嘱会被重复计数。这是指标语义层的经典错误，也是 [《NVIDIA Auto-Ontology 深度剖析》](/opensource/auto-ontology) 里 `SQL Attribute` 想固化的那类计算口径问题。修法是改聚合口径，不是把期望改成膨胀后的值。

## 七、实现与验证的证据边界

`〔COURSE_DESIGN〕` 若要由模拟推进到实测，最小的一条 CI 顺序是：结构/引用检查 → 类型与单元/契约检查 → 少量关键 E2E；每条结果附命令、退出码、环境、日志路径与复核人。这是**后续实施建议**，本仓库目前没有运行这些任务。

因此本分组交付的是：可交互的教学正文、可复位的实验台、显式规格与来源标记；**没有**交付 CafeFlow 式业务应用、真实后端运行证据或对任何外部项目的安装复现。站点 `pnpm build` 通过只证明页面可编译。

## 八、反例与取舍

- **什么时候独立 Oracle 会失效**：业务基线本身写错、或期望值由实现反向生成。前者要靠人工复核，后者正是本课的反例。
- **本层该发现的错误**：数值口径错误、断言失去独立性、模型升级后行为变化、负向用例缺失。
- **必须留到运行时的错误**：真实并发、真实权限会话、外部服务超时与不可逆副作用。
- **不承诺**：覆盖率数字等于质量；截图或 LLM 评价能替代数值断言；静态网站的 PASS 等于生产验收。

## 十、本分组收尾：三个问题

**06 分组解决了什么**：把 05 分组的架构从「能讲清楚」推进到「能按统一契约逐项检验」——变更有预览与审批、动作有六道门、故障有定位、结果有独立期望值，且每一句论断都标明它是规范、产品声明、课程设计还是实测结论。

**仍然不能解决什么**：全部交互都是浏览器内确定性推演。没有真实 HIS、Hono 后端、数据库事务、Playwright / Vitest 运行，也没有对外发单等不可逆副作用的实测。任何「已经跑通」的说法都需要另附证据。
